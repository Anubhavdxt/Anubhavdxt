Currently at Meltwater, working on social connection services, dealing with data at scale for enterprise
media intelligence. The interesting problems there are rarely about writing endpoints. They are about
keeping throughput up when a third-party API rate-limits you, how you backfill a missed window without
double-counting, and how you know your pipeline is slow before a customer tells you.

### What I build

**High-volume data ingestion** &nbsp;·&nbsp; Distributed collection against third-party platform APIs, event-driven pipelines, rate-limit and backfill handling, reconciliation of incomplete data.

**Applied LLM systems** &nbsp;·&nbsp; Fine-tuning small local models with LoRA and instruction tuning for classification and triage. Retrieval-augmented pipelines over multimodal sources with hybrid keyword and vector search. Agent workflows kept human-in-the-loop by design.

**Reliability and observability** &nbsp;·&nbsp; Instrumentation and dashboards for services that had no baseline, error budgets, failure recovery, alert tuning, logging cost control.

**Backend services and APIs** &nbsp;·&nbsp; Java and Spring Boot microservices, Node.js and Python services, schema and contract design, query and latency optimisation on PostgreSQL.

### Opinions I hold loosely

- You cannot tune what you have never measured. Most performance work I have done started with admitting there was no baseline.
- A small fine-tuned model that routes correctly beats a frontier API call on cost, latency and data residency.
- An agent that drafts and asks is more useful in an engineering team than one that acts and apologises.
- Currently reading about how transformers actually perform arithmetic. Not for work. It just bothers me that I do not know.
